# Code style used in this project

The project follows a few simple rules:

1. Use clear names that say what a value or function means.
2. Keep functions short and give each function one main job.
3. Prefer normal `if` statements over dense one-line expressions when the longer form is easier to read.
4. Keep error handling in a separate small function when possible.
5. Do not add a design pattern just because it exists. Use one only when it solves a real problem in the project.
6. Keep the project structure small enough that a student can follow the data flow from the ESP32 to the dashboard.
7. Keep tests for the main behavior so changes can be checked quickly.
